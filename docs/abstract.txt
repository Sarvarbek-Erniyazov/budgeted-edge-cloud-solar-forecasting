Short-term solar irradiance forecasts improve when ground measurements are combined with satellite imagery and numerical weather prediction (NWP), but such multimodal models run in the cloud, while a low-power device at a photovoltaic site sees only its own measurements. We ask how often such a device needs the cloud for intra-day global horizontal irradiance forecasting on the public Folsom benchmark. A compact on-device network using ground-sensor history is compared with a cloud forecaster that adds GOES-15 satellite patches and NWP forecasts available at issue time, and an on-device gate decides when to escalate a request. All settings and five claims were fixed on 2014-2015 data before a single evaluation on the held-out year 2016. There, the cloud forecaster lowers RMSE by 7.9% relative to the on-device network (70.7 versus 76.7 W/m2), and a day-block bootstrap interval excludes zero for all five seeds. With the model class held fixed, the cloud-side inputs lower RMSE by 4.2%, and a size-capped ground-only tree model is 3.7% worse than the cloud forecaster. An uncertainty-based gate retains 69% of the cloud gain while escalating 23% of requests, against 24% retained by random escalation; a learned gate is no better. Int8 quantization raises the on-device RMSE by 0.5 W/m2. Of the five claims, two were refuted and one partly: on development data the cloud-side inputs had appeared to add nothing, and no cloud advantage on ramp events had been found. The study is a single-site measurement, and latency was measured on a PC CPU only.
